1. PROBLEM STATEMENT
--------------------

Build an automated cryptocurrency trading system for BTC/USDT on a 15-minute
timeframe. The system must predict:

  (a) The direction (up/down) of the next 30-minute return (2 candles ahead)
  (b) The magnitude of that return

using a machine learning model. A separate decision layer decides whether to
trade based on predicted magnitude versus transaction costs (fees + slippage).

The system is intended to run paper trades on Binance Testnet, with eventual
deployment to a VPS for 24/7 operation. The project is intended as a minor MSc
project in Data Science and Applied Statistics.

2. INITIAL APPROACH (Session 1)
-------------------------------

  Timeframe    : 15-minute candles (native on most exchanges, balances
                 noise vs. fee viability)
  Asset        : BTC/USDT (most liquid, longest clean history, lowest slippage)
  Data         : 5 years of historical OHLCV (2020-01-01 to present)
                 Plus higher timeframe context (1h, 4h, 1d)
                 Derivatives data (funding rate, open interest) considered
                 but later deprioritized due to API restrictions
  Features     : ~45 engineered features across price/momentum, trend/
                 volatility, volume, higher-timeframe context, and cyclical
                 time encodings
  Labels       : Forward return over 2 candles (30 min)
                 Classification label: 1 if return > 0 else 0
                 Regression label: raw forward return
  Models       : XGBoost classifier (predicts P(up))
                 XGBoost regressor (predicts E[return])
                 Deep learning (TCN) considered as later challenger
  Validation   : Walk-forward. Train on 24 months, validate on 1 month,
                 test on next month. Roll forward monthly. 24 OOS test months.
  Decision     : Trade only if |E[return]| > total cost + safety margin
                 Total cost ~0.15-0.3% round trip
                 Position sizing scaled by magnitude, capped at 1-2% of account
                 Stop-loss/take-profit based on predicted magnitude
                 Daily loss limit and circuit breakers
  Execution    : Paper trading on Binance Testnet via CCXT
                 Local storage in Colab /content/crypto_data/ with manual
                 download/upload between sessions (no Google Drive permission)

8. TIMESTAMP HANDLING
---------------------

Binance changed the kline timestamp unit from milliseconds (13 digits) to
microseconds (16 digits) in January 2025. Detection:

    sample = int(df["open_time"].iloc[0])
    unit = "us" if len(str(sample)) >= 16 else "ms"
    df["ts"] = pd.to_datetime(df["open_time"], unit=unit, utc=True)

Without this detection, pd.to_datetime overflows and raises:
    Out of bounds nanosecond timestamp: 56971-10-25

PART III - OPTION A (Feature Stacking, Session 2)

9. ARCHITECTURE
---------------

    +-----------------------------------------+
    |  5m features   --+                      |
    |  15m features  --+                      |
    |  1h features   --+-- ONE LightGBM --> signal
    |  4h features   --+                      |
    +-----------------------------------------+

All features across all timeframes concatenated into one matrix. One model
learns everything jointly, including cross-timeframe interactions.

The model is trained on 5m bars (the natural trading resolution) but sees
higher-timeframe context through feature stacking.

10. FEATURES
------------

Same 14 features computed per timeframe with prefix (5m_, 15m_, 1h_, 4h_):

    Category          Features
    --------------    ------------------------------------------------
    Returns           ret_1, ret_3, ret_6, ret_12
    Volatility        vol_12 (rolling std), atr_14 (normalized by close)
    Oscillator        rsi_14
    Trend             ema_ratio = EMA(12) / EMA(48) - 1
    Volume            vol_z (48-bar z-score of volume)
    Candle shape      body, upper_wick, lower_wick
    Time              hour, dow

Total: 14 x 4 = 56 features.

All features are stationary - returns, ratios, z-scores. No raw prices.

11. MULTI-TIMEFRAME ALIGNMENT
-----------------------------

At a 5m bar with timestamp t, the higher-timeframe (1h, 4h) candles at that
moment are STILL FORMING. Using their current close/high/low would leak future
information.

Solution - only use the last fully closed higher-TF candle:

    aligned = hi[cols].reindex(base.index, method="ffill").shift(1)

  - reindex(..., method="ffill") broadcasts the higher-TF value to every 5m bar
  - .shift(1) pushes it back by one 5m row, ensuring the currently-forming
    higher-TF candle is never used

VERIFICATION - double-shift leak test on 4h_ret_1 (the highest-importance
feature):

    Normal                       : 0.6147
    4h_ret_1 shifted by 2 more   : 0.6150

If it had been leaking, the extra shift would have collapsed accuracy to
~0.33 (random). It didn't. Alignment is clean.

12. LABELS
----------

    fwd = close.shift(-12) / close - 1     # 12 bars = 60 min
    y = +1 if fwd >  0.0015                # up > 0.15%
        -1 if fwd < -0.0015                # down > 0.15%
         0 otherwise                        # no trade

THRESHOLDED labels (not raw up/down). Threshold ~= round-trip cost. Forces
model to predict only meaningful moves.

Class balance:
    -1 (short)    : ~25%
     0 (no-trade) : ~50%
    +1 (long)     : ~25%

13. MODEL - LIGHTGBM MULTICLASS
--------------------------------

    PARAMS = dict(
        objective="multiclass", num_class=3,
        learning_rate=0.03, num_leaves=31,
        min_data_in_leaf=200, feature_fraction=0.8,
        bagging_fraction=0.8, bagging_freq=1, verbose=-1,
    )
    num_boost_round = 400

WHY LIGHTGBM (vs XGBoost originally planned):
  - Tabular data: GBDTs dominate on mixed features
  - Fast: trains 40k-row folds in seconds
  - Robust to feature scale: no normalization needed
  - Handles NaN natively: warmup rows don't break training
  - Interpretable: feature_importance("gain")
  - Standard for tabular alpha research

14. WALK-FORWARD VALIDATION
---------------------------

    Fold 0: [--train--][emb][-test-]
    Fold 1: [----train----][emb][-test-]
    Fold 2: [------train------][emb][-test-]
    Fold 3: [--------train--------][emb][-test-]
    Fold 4: [----------train----------][emb][-test-]
    Fold 5: [------------train------------][emb][-test-]

6 folds, ~40k bars per fold, 12-bar embargo between train and test.

Because label at bar t uses prices up to bar t+12, the test window must start
at least 12 bars after training ends.

Predictions on all test windows concatenated = OOS signal for entire period.

18. BACKTEST ITERATIONS AND BUG FIXES
-------------------------------------

18.1 v1 - NAIVE COMPOUNDING (BROKEN)
-------------------------------------

Setup:
    gross = (exit_open / entry_open - 1) * signal
    net = gross - signal.abs() * 2 * COST
    equity = (1 + net).cumprod()

Result: final equity 1,149,370 (from $1), Sharpe 6.46, 71,755 trades.

DIAGNOSIS: Signals fired 30% of bars, each opening a separate trade with a
12-bar hold. Positions overlapped heavily. Each 12-bar return attributed to
the entry bar and compounded. Equity multiplied dozens of overlapping returns.

FIX: One position at a time.

18.2 v2 - OVER-LEVERAGED
------------------------

Setup:
    atr = (high - low).rolling(14).mean()
    stop_dist = (1.5 * atr / close).clip(lower=1e-4)
    size = (RISK_FRAC / stop_dist).clip(upper=MAX_LEV)

Result: equity 20.78, Sharpe 5.18, 4,840 trades, hit rate 0.745, DD -9.5%.

DIAGNOSIS: With RISK_FRAC=0.01 and typical stop_dist around 0.005-0.01,
RISK_FRAC/stop_dist is 1-2, then .clip(upper=1.0) pins to 1.0. Every trade
risks 100% of equity.

FIX: Deterministic sizing based on fixed stop distance.

18.3 v3 - CURRENT HONEST VERSION
---------------------------------

    STOP_DIST_PCT = 0.01
    base_size = min(RISK_FRAC / STOP_DIST_PCT, MAX_LEV)
    size = position.abs() * base_size

With RISK_FRAC=0.005 and STOP_DIST_PCT=0.01, size = 0.5 (50% per trade).

Result: equity ~4.5, Sharpe ~5, DD ~5%.

20. RANDOM-SIGNAL CONTROL TEST
------------------------------

PURPOSE: If the backtest has a mechanical bug (compounding, overlapping,
lookahead), random signals would also appear profitable.

Setup:
    np.random.seed(42)
    n_trades = (sig_real != 0).sum()
    rnd_sig = random choice of n_trades bars, direction +1
    rnd_sig = rnd_sig.where(sign(rnd_sig) == gate, 0).fillna(0)

Result:
    Final equity        : 0.001  (lost 99.9%)
    Sharpe              : -17.08
    Max drawdown        : -99.9%
    Trades              : 9,675
    Hit rate            : 0.503  (chance)
    Profit factor       : 1.04

INTERPRETATION: Random signal behaves exactly as a control should - chance
hit rate, breakeven gross, ruin after fees. The backtest is honest.

21. COST SENSITIVITY TEST
-------------------------

First attempt output (BROKEN):
    COST=0.0015  sharpe=5.17  equity=4.678
    COST=0.0025  sharpe=5.17  equity=4.678   <-- identical
    COST=0.0035  sharpe=5.17  equity=4.678   <-- identical
    COST=0.0050  sharpe=5.17  equity=4.678   <-- identical

DIAGNOSIS: backtest_final.py defined COST at module level but compute_pnl
used a default argument: def compute_pnl(..., cost=COST). Default arguments
bind at definition time, so bf.COST = 0.005 from outside had no effect.

FIX:
    def compute_pnl(ohlcv, position, size, cost=None):
        if cost is None:
            cost = COST

Expected behavior after fix:
    0.0015 -> Sharpe ~5
    0.0025 -> Sharpe ~3
    0.0035 -> Sharpe ~2
    0.0050 -> Sharpe ~1

If Sharpe stays positive past 0.5% round-trip, edge is robust.

22. MOTIVATION
--------------

After Option A succeeded with Sharpe ~5 and 74% hit rate, two hypotheses:

  H1: Real edge - model found genuine short-term momentum pattern.
  H2: Subtle leak - some feature uses future info, random-signal test didn't
      catch it (because random trades also suffered from the leak).

Option B was designed as a FALSIFICATION TEST:

    If the edge is real, it should survive any reasonable architecture.
    If it's an artifact of feature stacking, splitting into separate models
    should either destroy the edge or reveal the leak.

Secondary motivation: Hierarchical models are mainstream in structured
prediction (HRM, options pricing, portfolio allocation). If they work here,
natural progression.

23. ARCHITECTURE
----------------

    +-----------------------------------------------------+
    |  4h OHLCV (5,844 bars)                              |
    |       |                                             |
    |       v                                             |
    |   add_features(prefix="4h")                         |
    |       |                                             |
    |       v                                             |
    |   +-------------------+                             |
    |   | L1: Regime        |                             |
    |   | 3-class softmax   |--> p_down, p_range, p_up    |
    |   +-------------------+                             |
    |       |                                             |
    |       | shift(1) + reindex to 1h                    |
    |       v                                             |
    |   +------------------------------------------+     |
    |   | 1h OHLCV + L1 preds + 5m aggregates      |     |
    |   |       |                                  |     |
    |   |       v                                  |     |
    |   |   +-------------------+                  |     |
    |   |   | L2: Direction     |                  |     |
    |   |   | 3-class softmax   |--> p_short, p_no, p_long
    |   |   +-------------------+                  |     |
    |   +------------------------------------------+     |
    |       |                                             |
    |       | shift(1) + reindex to 5m                    |
    |       v                                             |
    |   +------------------------------------------+     |
    |   | 5m OHLCV + L1 preds + L2 preds           |     |
    |   |       |                                  |     |
    |   |       v                                  |     |
    |   |   +-------------------+                  |     |
    |   |   | L3: Trigger       |                  |     |
    |   |   | binary            |--> p_enter       |     |
    |   |   +-------------------+                  |     |
    |   +------------------------------------------+     |
    |       |                                             |
    |       v                                             |
    |   Fusion (hard AND or soft product)                 |
    |       |                                             |
    |       v                                             |
    |   Final signal in {-1, 0, +1}                       |
    +-----------------------------------------------------+

24. LEVEL DESIGNS
-----------------

L1 - 4h Regime Classifier
    Target     : +1.5% over 24h -> up; -1.5% -> down; else range
    Features   : 14 4h_* only
    Class bal. : down 20.8%, range 57.6%, up 21.6%

L2 - 1h Direction Classifier
    Target     : +0.3% over 6h -> long; -0.3% -> short; else no-trade
    Features   : 14 1h_* + L1 predictions + 5m aggregates (v2 fix)
    5m agg     : mean/std of ret_1, mean of atr_14, rsi_14, vol_z, body

L3 - 5m Trigger Classifier
    v1 target  : |fwd_12| > 0.15% -> binary
    v2 target  : conditional on L2 direction
    Features   : 14 5m_* + L1 + L2 predictions

25. FUSION STRATEGIES
---------------------

Hard (AND):
    signal = +1  if  up_regime AND long_dir AND trig_ok

Soft (product):
    score_long = p_up * p_long * p_enter
    signal = +1  if score_long > 0.15

29. DIAGNOSIS - WHY OPTION B FAILED
-----------------------------------

29.1 INFORMATION LOSS (core problem)

In Option B:
    L3 never sees 1h features
    L2 never sees 5m candles
    L1 never sees lower-timeframe data at all

The alpha lives in JOINT PATTERNS across timeframes, e.g.:
    "When 4h trend is up AND 1h momentum positive AND 5m RSI dipped below 30
     AND 5m ATR spiked - this is a high-probability long entry."

Option A CAN learn this (single joint model has all features).
Option B CANNOT - each level only has partial info.
The joint pattern is UNREPRESENTABLE in a hierarchical architecture.

29.2 MULTIPLICATIVE ERROR

Three models, each ~55-60% accurate, compose as:
    P(all correct) ~= 0.55 x 0.57 x 0.60 ~= 0.19

31. SCIENTIFIC CONCLUSION
-------------------------

PRIMARY FINDING:
Feature stacking (Option A) STRICTLY DOMINATES prediction stacking (Option B)
for multi-timeframe financial prediction.

Reason: any function computable from stacked predictions is computable from
stacked features, but not vice versa. The alpha lives in the joint distribution
P(return | 5m, 1h, 4h), which Option B cannot represent.

SECONDARY FINDING:
Intermediate targets must be aligned with the final objective. Option B's
three models optimize proxy targets that don't compose.

WHEN HIERARCHICAL MODELS DO WORK:
  - Feature spaces are genuinely incompatible (text + image)
  - Training data is heterogeneous
  - Interpretability requires decomposition
  - Levels trained on different data

None apply to "same OHLCV data, different timeframes."

FINAL VERDICT:
Do not pursue Option B further. Continue developing Option A.

APPENDIX A - LESSONS LEARNED
----------------------------

TECHNICAL:
  - Sub-second backtest isn't enough. Our first backtest had a compounding
    bug that took 3 iterations to find.
  - "Random signal control" is essential. It caught the compounding bug.
  - Balance checks matter. L3's v1 target was 65% positive - model couldn't
    be selective with a skewed target.
  - Walk-forward is not optional.
  - The original plan's XGBoost classifier + regressor combo was replaced
    with a single LightGBM multiclass with thresholded labels. Simpler and
    equivalent.

DATA:
  - Binance Vision (data.binance.vision) is the answer for geo-blocked
    historical data. No API key, no rate limits, no geo-block. Serve zipped
    CSVs directly.
  - Always auto-detect timestamp units (ms vs us).
  - Validate timestamp ranges after download to catch partial failures.

RESEARCH PROCESS:
  - Two failures are worth recording. Option B's failure is a legitimate
    scientific finding, not a waste of time.
  - Negative results sharpen hypotheses. We now know WHY Option A works.
  - Always test architecture against a baseline.

PERSONAL:
  - 74% hit rate is suspicious. Random-signal test is the correct way to
    distinguish real edge from artifact.
  - Data alignment is where most bugs hide. shift(1) on reindexed frames is
    a classic source of subtle lookahead.
  - Position sizing changes everything. Same signal, 100%-equity sizing gives
    Sharpe 5.18 and equity 20.78; 0.5%-risk sizing gives Sharpe ~5 and equity
    4.5. Sharpe is leverage-invariant; equity curve is not.

APPENDIX C - GLOSSARY
---------------------

Alpha              : Excess return not attributable to market movement.
Drawdown (DD)      : Peak-to-trough decline in equity.
Embargo            : Gap between train and test in walk-forward.
Feature stacking   : Concatenating features from multiple sources into one model.
Hit rate           : Fraction of trades with positive PnL.
MTF                : Multi-timeframe.
Prediction stacking: Chaining models where each consumes previous output.
Profit factor (PF) : Gross wins / gross losses.
Regime             : Broad market state (up / range / down).
Sharpe ratio       : Annualized return / annualized volatility.
Walk-forward       : Sequential train-then-test with rolling windows.
